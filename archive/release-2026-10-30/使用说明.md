# Coco 电机、唤醒与预置回答完整包

本包对应两块 ESP32-S3：语音板 84:C7:BB:5A:AE:DC，原电机板 84:C7:BB:58:E7:88。串口号会变化，刷写脚本会检查 MAC。双麦暂未启用。开发板不接屏幕，使用 NoDisplay。

## 已实现

- 语音板通过 G13/G14 串口控制原电机板，保留遥控优先、CRC、会话和序号校验、250ms 运动超时、显式停止和换向停顿。
- 唤醒词为“嘿 Coco”，按“嘿扣扣”发音；模型命令为 `hei kou kou`，显示名称为“嘿Coco”。识别阈值从35%调整为源码默认20%，现场效果以验证记录为准。
- 唤醒时立即播放本地“我在”。尚未建立服务器控制连接时，播放“我在。正在连接服务器。”；MQTT 已登录或 WebSocket 已连接时只播放“我在”，避免为打开约百毫秒的音频通道多说一整句提示。提示音与握手同时进行，服务器及时收到监听控制消息，提示音结束后再开放麦克风上传，避免机器人把自己说的话当作用户输入。
- 提示音、预置回答由这块设备已绑定的小智服务生成，使用生成时的当前音色；服务器返回文字已经逐字核对。它们是固定缓存，今后在控制台换音色不会自动改变这些音频。
- 对话1：“我来自烟台理工学院。”只播放 Coco 的回答，主持人台词不播放。当前文件约 3.36 秒，已打包在资源分区，无需每次请求大模型。
- 同一段再次触发时中断旧播放、从头重播；播放期间停止麦克风上传与唤醒检测，播放结束恢复待机唤醒。
- 预留“指定编号播放”“顺序播放下一段”“停止播放”接口。只配置了编号1，编号2～16不会播放虚构内容。
- 保持 Wi-Fi 性能模式，关闭唤醒录音上传，连接存在时复用连接，并记录实际握手耗时。云端推理、TTS 和网络延迟仍会影响普通对话；本地提示音不是连接成功的证明。
- Coco 专用麦克风转换默认增益4倍，替代通用代码固定约16倍放大，降低实测削波。`COCO MIC GAIN 1`～`COCO MIC GAIN 16` 可临时调整，重启恢复4倍；累计削波数不会在调整增益时清零。
- 修复无屏幕设备在加载资源时创建 LVGL 字体、触发空指针重启的问题：无 GUI 时仍加载语音模型，但跳过字体、表情和主题资源。

## 文件布局

- `firmware/voice/`：小智板分段固件与烧录清单。
- `firmware/motor/`：电机板 Arduino 应用、启动和分区固件。
- `firmware/remote/`：保留原遥控界面、增加调用接口后的编译结果。尚未安排新的对话按钮，不需要现在刷遥控器。
- `source/voice/`：完整小智工程及锁定依赖，含自定义板型、音频和构建脚本。
- `source/motor/`：完整电机源码与协议测试。
- `source/remote/`：遥控器完整源码、厂家已配置屏幕库和触摸库。
- `audio-preview/`：提示与对话音频的 WAV 试听。
- `validation.md`：本次验证结果和仍需实物验证的部分。

## 接线

所有接线先断电。保留已验证有效的 5cm 麦克风线。

| 模块 | 小智语音板 |
|---|---|
| INMP441 WS | G4 |
| INMP441 SCK | G5 |
| INMP441 SD | G6 |
| INMP441 VDD / GND / L/R | 3V3 / GND / GND |
| 功放 DIN / BCLK / LRC | G7 / G15 / G16 |
| 功放 GAIN / SD / GND / VIN | 悬空 / 3V3 / GND / 5V（限支持5V的原模块） |
| 小智串口 TX / RX | G13 / G14 |

小智 G13→电机 G14，小智 G14←电机 G13，GND 共地。电机板仍为左履带 G15/G16、右履带 G4/G5、躯干 G6/G7。躯干保持停止，履带输出仍为用户要求的 100%。两块板的同号引脚用途不同。

## 烧录

关闭占用串口的监视器，确认目标板身份，电机测试时履带悬空。脚本只备份配置和写固件，不发送运动命令。

在本包目录运行（端口以当前设备为准）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Flash-Device.ps1 -Target voice -Port COM13
powershell -NoProfile -ExecutionPolicy Bypass -File .\Flash-Device.ps1 -Target motor -Port COMxx
```

脚本寻找本机 Arduino esptool，也可通过 `-EsptoolPath` 指定。它先校验固件、核对 MAC、备份前64KB，再分段写入，避免清空 NVS。首次使用新板型可能需要重新配网；服务器绑定按已有设备身份处理，不包含任何改 MAC 或绕过绑定的逻辑。

语音板地址：启动0x0、分区0x8000、OTA数据0xd000、应用0x20000、资源0x800000。电机板仅更新应用0x10000，保留原分区、引脚映射与遥控配对。不要混刷两种应用地址。

若是从未配置的新电机板，串口发 `PINS 15 16 4 5 6 7`，成功后发 `REBOOT`；原板已有配置无需重复设置。

## 立即测试预置回答

语音板 USB 串口 115200，每行回车：

```text
COCO STATUS
COCO DIALOG 1
COCO DIALOG NEXT
COCO DIALOG STOP
```

这些播放命令不会驱动电机。再发一次 `COCO DIALOG 1` 可以测试从头重播。播放时说唤醒词应不打断台词。

`COCO STATUS` 同时显示唤醒检测开关、当前输入峰值与累计削波数。`COCO WAKE` 仅供诊断本地提示和连接流程，会软件触发唤醒，不能作为麦克风成功识别的证明。

电机板 USB 串口 115200 也预留：`DIALOG 1`、`DIALOG NEXT`、`DIALOG STOP`。必须先接通两板串口；语音板会验证反向事件的 CRC、会话和递增序号。两端刷本包版本后使用。

运动测试命令仍为语音板 `COCO TEST FORWARD 300` 和 `COCO STOP`。只有确认 H 桥上电、履带悬空且接线恢复后再测试；日志输出不等于实际电机运动。

## 将来添加遥控按钮

在 `source/remote/WallERemote/remote_app.h` 预留了：

```cpp
remotePlayDialogue(1);      // 指定编号
remotePlayNextDialogue();   // 顺序播放；目前只有一段
remoteStopDialogue();       // 停止当前预置回答
```

从现有 UI 任务调用即可。返回 true 表示已进入本地待发槽，不代表机器人已播放。暂不分配触摸区域或占用原来的方向键。命令使用独立 ESP-NOW 类型7，不会把对话编号解释成电机油门；只有已配对、有效会话和新序号的遥控包才会被转发。断线/重新配对会丢弃尚未发出的对话请求。

## 修改台词或唤醒词

预置表：`source/voice/main/boards/coco-voice-uart/coco_presets.h`。音频在同目录 `sounds/`，格式为单声道 Ogg Opus。替换台词时必须同时替换相应音频；只改字幕不会改变实际播出的内容。重新生成当前音色需要使用自己的小智设备/语音服务，包中不含访问令牌。

包内 `tools/generate_current_voice.py` 提供与本次相同的生成办法：Windows 内置慧慧音色合成请求，发送给自己的已绑定设备服务，保存服务器当前音色的回答；返回台词与请求不一致时拒绝打包。需安装 `tools/requirements.txt`，修改 `tools/coco_speech_lines.json`，然后运行：

```powershell
python tools/generate_current_voice.py --device-id 84:c7:bb:5a:ae:dc --client-id 设备启动日志中的UUID
```

已有同名 `.ogg` 默认跳过，替换前先备份并移走要重新生成的文件。该工具需要联网和 Windows“Microsoft Huihui Desktop”语音组件，令牌只保存在内存中。生成后重新构建语音板资源和固件。

唤醒配置：该板 `config.json` 的 `CONFIG_CUSTOM_WAKE_WORD`、`CONFIG_CUSTOM_WAKE_WORD_DISPLAY` 和 `CONFIG_CUSTOM_WAKE_WORD_THRESHOLD`。配置改变后要重建固件和 `generated_assets.bin`，不能只改控制台名字。

## 从源码编译

语音工程使用 ESP-IDF 6.1，最低6.0.1，不能用 IDF5。先按官方方式安装并启用 SDK，然后：

```powershell
cd source/voice
$env:CMAKE_NINJA_FORCE_RESPONSE_FILE='1'
python scripts/build.py coco-voice-uart --name coco-voice-uart --language zh-CN
```

不要加 `--wake-word nihaoxiaozhi`，那会覆盖自定义模型选择。本包包含 `managed_components` 和模型，按锁定依赖构建；生成的 build/sdkconfig 不随源码打包，构建脚本会重新生成。

电机使用 Arduino ESP32 3.3.10-cn，FQBN：

```text
esp32:esp32:esp32s3:USBMode=hwcdc,CDCOnBoot=default,FlashMode=dio,FlashSize=16M,PartitionScheme=app3M_fat9M_16MB,PSRAM=opi
```

遥控器用相同目标，但 `CDCOnBoot=cdc`，并把 `source/remote/libraries` 传给 arduino-cli 的 `--libraries`。保持厂家 TFT_eSPI 配置，勿换成默认屏幕引脚。
